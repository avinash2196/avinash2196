## Prompt-Driven Development

I am developing a reusable engineering approach for integrating AI coding assistants into software delivery without giving up **architectural discipline, traceability, testing rigor, or human accountability**.

The approach evolved from using large project-specific prompts into separating reusable engineering responsibilities across:

* **Agents** — define focused engineering roles and responsibilities
* **Skills** — provide reusable technical workflows and domain guidance
* **Prompts** — initiate specific stages of the development lifecycle
* **Repository instructions** — establish project-wide engineering boundaries
* **Project artifacts** — preserve requirements, plans, decisions, and implementation context across AI sessions

A typical change progresses through:

**Requirements → Plan → Human Review → Implementation Plan → Human Review → RED Tests → GREEN Implementation → Refactor → Validation → Final Review**

The planning stages inspect the existing repository structure and current project state before proposing implementation changes.

The implementation plan can therefore be reviewed before code is modified, while project artifacts are updated as development progresses so that important engineering context does not disappear when an AI conversation ends.

### Engineering Control Boundaries

The workflow establishes explicit boundaries for AI-assisted development, including:

* do not invent requirements, business rules, or architectural decisions when material behavior is unclear
* clarify significant ambiguity before implementation
* do not approve plans or architectural decisions on behalf of human reviewers
* keep RED, GREEN, and optional REFACTOR stages separate
* preserve public contracts unless an approved change explicitly modifies them
* avoid pulling future milestone work into the current implementation
* verify tests, builds, validations, and migrations instead of claiming unexecuted work succeeded
* prefer the smallest safe change that satisfies the approved scope
* maintain repository context so future changes can build on previous engineering decisions

The goal is not simply to generate code faster.

It is to make AI-assisted software development:

* **reviewable** — engineers can inspect intended changes before implementation
* **controlled** — humans retain authority over requirements and architecture
* **traceable** — implementation can be connected back to reviewed plans and decisions
* **testable** — behavioral changes are supported through explicit RED/GREEN development
* **repeatable** — reusable engineering standards can be applied across repositories
* **maintainable** — project context and engineering decisions persist as the codebase evolves
